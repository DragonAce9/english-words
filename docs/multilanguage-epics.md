# Новые языки в приложении: эпики и задачи для исполнителя

Документ для ИИ-исполнителя. Задачи выполняются по порядку внутри эпика; эпики E1 → E5 последовательно, E2 и E3 могут идти параллельно с E4 после завершения E1.

## Контекст

Telegram Mini App для изучения английских слов. Интерфейс и значения на русском. Пользователь учит набор слов (тема, фильм/серия, свой текст) четырьмя шагами: 1. Пары, 2. Учить, 3. Контрольная, 4. Экзамен. Питомец Моти, монетки, подписка через Tribute, рефералы.

Стек: `packages/web` (Vite + React, без роутера, навигация через union-тип `Screen` в `App.tsx`), `packages/api` (Hono + grammY в одном процессе Node), Postgres, Docker Compose. Каталог слов лежит в файлах `data/themes/*.json`, `data/media/*.json`, `data/blocks.json` и копируется в образ при сборке. Миграции в `migrations/*.sql` выполняются при старте API.

Модель слова сейчас: `word_id` — slug английской леммы (`slugWord(en)` в `packages/api/src/userWords.ts`, `senses.ts`). Прогресс в `word_progress` по ключу `(user_id, word_id)`: `status`, `rewarded`, `examined`, `known_on`, `control_passed`. Одна лемма может лежать в нескольких темах с разными русскими значениями (пример: `cock` — «петух» в `animals.json`, «член» в `body.json`). Фильмы используют те же `word_id`, что и темы.

Текущая версия в проде. Каждый релиз должен быть совместим с предыдущим образом и базой.

## Правила для исполнителя

- Не коммитить и не пушить без явного указания. Не печатать значения из `.env`.
- Не запускать `npm run dev:api`: порт 3000 занят Docker. Для проверки UI пересобирать образ: `docker compose up -d --build api` из корня.
- Dev-пользователь `telegram_user_id=1` / `users.id=11` остаётся на бесплатном тарифе. Не отмечать его слова массово.
- Внутри Telegram не писать `location.hash`.
- Тексты интерфейса и бота на русском.
- Не скачивать субтитры и постеры с rezka.ag и 2sub.movie. OpenSubtitles только через существующий официальный API.
- Один упавший тест уже есть до начала работ: канал ежедневного факта. Его не трогать, если новая работа его не ломает.
- Любое изменение схемы — только добавление. Ничего не удалять и не переименовывать в базе в рамках этого плана.
- Перед каждым релизом: `pg_dump` базы из контейнера Postgres в папку бекапов, прогон всех тестов API, запуск нового образа на копии базы.

## Термины

- **Код языка** — `en`, `fr`, `de`, `es`. Язык изучаемых слов. Русский — всегда язык значений и интерфейса.
- **Исходная карточка** — английская карточка каталога.
- **`sourceId`** — поле карточки нового языка со ссылкой на `word_id` исходной английской карточки.
- **Пара перевода** — уникальная комбинация «английский `word_id` + русское значение + часть речи». Единица, которую переводит модель.
- **Пул** — набор слов одной темы, одного фильма/серии или одного текста на текущем языке.

## E1. Язык в модели данных

Цель: язык становится частью ключа у пользователя, прогресса, сохранённых слов и каталога. Для английского поведение не меняется. Релиз совместим со старым образом.

### E1.1 Миграция: колонка языка

Файл: новый `migrations/<следующий номер>_languages.sql`.

- `users.language text not null default 'en'`.
- `word_progress.language text not null default 'en'`; первичный ключ `(user_id, language, word_id)`. Старый уникальный индекс оставить до конца релиза, если он нужен старому коду.
- Та же колонка со значением по умолчанию `en` в `user_study_words`, `user_words`, `catalog_words`, таблице выбранных тем «Изучаю» и таблице заявленного бесплатного фильма (найти по коду `claim` / медиа-лимита).
- Рефералы, Моти, подписка, монетки без изменений.

Критерии: миграция проходит на копии прод-базы; все существующие строки получили `en`; старый образ API запускается с новой базой и работает.

### E1.2 Каталог по языкам в файлах

- Переместить `data/themes`, `data/media`, `data/blocks.json`, `data/word-pos.json` в `data/en/…`. `data/legal.json` остаётся общим.
- Загрузчик (`packages/api/src/dictionary.ts`, `catalog.ts`, `themeFile.ts`) строит путь от `DICTIONARY_DIR` + код языка. Один экземпляр словаря на язык, загруженные при старте.
- Если `data/en` пуст, а старый `data/themes` есть — читать старый путь и писать предупреждение в лог. Убрать в следующем релизе.
- Все места, которые пишут в файлы тем (`appendThemeWord`, `fileCatalogLemma`, `fileMediaLemma`, `scripts/import-media.ts`, `scripts/file-catalog-categories.ts`), получают язык параметром; сейчас везде `en`.
- `Dockerfile` копирует `data/` целиком, как и раньше.

Критерии: `/health` и счётчик на главной показывают прежнее число (12 793 на момент написания); тесты `lookup.test.ts`, `app.test.ts` проходят.

### E1.3 Язык пользователя в API

- `users.language` читается в `auth.ts` вместе с пользователем и кладётся в контекст запроса.
- Все обработчики, где есть слово, тема, сессия, прогресс, статистика, экзамен, «Изучаю», «Мои слова», свой текст, бесплатный фильм — берут язык из контекста пользователя. Язык не принимается параметром запроса.
- `GET /me` (или существующий эндпоинт профиля) отдаёт `language`.
- Новый `POST /me/language` с телом `{ language }`; принимает только код из списка доступных языков (E4.1), иначе 400.

Критерии: тест — прогресс по слову в `en` не виден после смены языка пользователя на `fr` и наоборот; контрольная и экзамен берут слова только текущего языка; правило одной опечатки сравнивает с пулом текущего языка; бесплатные лимиты считаются на язык.

### E1.4 Тип карточки

Файл: `packages/api/src/types.ts`, зеркально в типах `packages/web`.

- `DictWord` получает необязательные поля: `sourceId?: string`, `gender?: "m" | "f" | "n"`, `word: string` как слово на изучаемом языке. Для английского `word === en`. Поле `en` остаётся для совместимости; новый код читает `word`.
- `Direction` переименовывается в смысле «целевой ↔ русский»; значения `en-ru` / `ru-en` сохраняются как есть, чтобы не ломать клиент, но комментарий в типе фиксирует, что `en` означает «изучаемый язык».

Критерии: сборка web и api без ошибок типов; существующие темы грузятся без правок файлов (поле `word` подставляется из `en` при загрузке).

### E1.5 Релиз 1

- `pg_dump` в `~/Backups/`.
- Полный прогон тестов API. Запуск образа на копии базы.
- `docker compose up -d --build api`.
- Проверка в браузере (`http://127.0.0.1:3000/`, dev-режим) и в Telegram: главная, тема «Числа», четыре шага, фильм, свой текст, статистика, счётчик.

Критерии: пользователи не видят изменений; dev-прогресс на месте.

## E2. Генерация каталога на новый язык

Цель: скрипт собирает `data/<lang>/` из `data/en/` через перевод пар. Первый язык — `fr`. В прод не выкатывается до E4.

### E2.1 Сбор пар перевода

Файл: `scripts/lang/collect-pairs.ts`.

- Пройти все темы и паки `data/en`. Для каждой карточки взять `(id, ru[], pos)`. Уникальный ключ — `id + нормализованная строка ru + pos`.
- Сохранить в `data/<lang>/.cache/pairs.json` с полями: ключ, `en`, `ru`, `pos`, `level`, первый английский пример, список тем и паков, где пара встречается.
- Вывести отчёт: число карточек, число уникальных пар, число `id` с более чем одним значением.

Критерии: число пар заметно меньше числа вхождений; `cock` даёт две пары.

### E2.2 Перевод пар моделью

Файл: `scripts/lang/translate-pairs.ts`. Использовать уже настроенный клиент Gemini (`GEMINI_*` в `.env`), не добавлять нового провайдера.

- Вход: пара из E2.1. Запрос содержит английское слово, русское значение, часть речи, английский пример и целевой язык.
- Ответ строго в JSON: `word` (словарная форма без артикля), `gender` для существительных, `example` (одно короткое предложение на целевом языке с этим словом), `note` если модель считает, что значение неоднозначно.
- Кэш в `data/<lang>/.cache/translations.json` по ключу пары. Повторный запуск не переводит уже готовые. Параллельность ограничена, повтор при ошибке сети.
- Отчёт после прогона: пустые ответы, ответы, совпавшие с английским словом, французские слова, которые получились одинаковыми у разных английских `id` (кандидаты на склейку), пары с `note`.

Критерии: прогон на 50 парах даёт валидный JSON без ручной правки; полный прогон завершается с отчётом.

### E2.3 Сборка тем

Файл: `scripts/lang/build-themes.ts`.

- Для каждой темы `data/en/themes/<id>.json` создать `data/<lang>/themes/<id>.json` с тем же `id`, `title`, `paid`, `blockId`.
- Карточка: `id` = slug французского слова; если два разных французских слова происходят от одного английского `id`, это две карточки с разными `id`. Поля: `word`, `sourceId`, `ru` (с английской карточки), `gender`, `example`, `level` (с английской карточки), `pos`.
- Если одно французское слово получилось из двух разных английских `id` в одной теме — объединить в одну карточку с двумя `sourceId` только если `ru` совпадает; иначе оставить обе и записать в отчёт.
- `data/<lang>/blocks.json` копируется из `en` без изменений.

Критерии: число тем совпадает с `en`; загрузчик API читает `data/fr` без ошибок; на карточке с `sourceId` можно найти исходную английскую.

### E2.4 Сборка паков кино

Файл: `scripts/lang/build-media.ts`.

- Для каждого пака `data/en/media/<id>.json` создать `data/<lang>/media/<id>.json` с теми же метаданными: название, год, постер, `kind`, `showId`, серия.
- Список карточек — те же пары, что в английском паке, подставлены французские карточки из E2.3. Состав слов не меняется.
- Пример к слову: перевод короткой английской реплики из пака моделью (отдельный кэш `data/<lang>/.cache/media-lines.json`). В файле пака поле `exampleTranslated: true`.

Критерии: число паков совпадает с `en`; в каждом паке число карточек равно английскому ± склейки из E2.3 отчёта.

### E2.5 Отчёт для ревью

Файл: `scripts/lang/review-report.ts`.

- Выгрузка одной темы целиком и случайной выборки 100 карточек из разных тем + 30 из одного фильма в `data/<lang>/.cache/review.md`: английское слово, русское значение, французское слово, род, пример.
- Правки вносятся в `translations.json`; `build-themes` и `build-media` пересобирают без новых запросов.

Критерии: пересборка после правки одной записи меняет все темы и паки, где эта пара встречается.

## E3. Ревью французского каталога

Выполняет человек по отчёту E2.5. Исполнитель ИИ только вносит правки в кэш и пересобирает.

### E3.1 Первичное ревью
Тема целиком + 100 + 30 карточек. Критерии проверки: слово соответствует русскому значению этой карточки; словарная форма без артикля; род верный; пример естественный и содержит слово.

### E3.2 Склейки и пустые
Разобрать список кандидатов на склейку и пустых ответов из отчёта E2.2. Для каждого — оставить, разделить или удалить карточку.

### E3.3 Жалобы после запуска
Кнопка жалобы на карточке уже есть. Сообщения в поддержку по французским карточкам правятся через `translations.json` и пересборку. Отдельного механизма не делать.

## E4. Выбор языка в приложении

Цель: экран выбора на старте, смена из настроек, озвучка по языку, скрытие недоступных входов. Выкатывается с одним языком в списке; французский включается конфигурацией.

### E4.1 Список доступных языков

- Переменная окружения `AVAILABLE_LANGUAGES`, по умолчанию `en`. API отдаёт список в `GET /me` или в конфиге приложения: код, русское название («Английский», «Французский»), код голоса озвучки (`en-US`, `fr-FR`), флаги возможностей: `dictionary`, `texts`, `mediaRequests`.
- Для `en` все возможности включены. Для остальных языков в первой версии `dictionary=false`, `texts=false`, `mediaRequests=false`.

Критерии: при `AVAILABLE_LANGUAGES=en` ответ содержит один язык.

### E4.2 Экран выбора на старте

Файлы: `packages/web/src/App.tsx`, новый `views/LanguagePick.tsx`.

- Показывается до `welcome`/главной, если доступных языков больше одного и у пользователя язык ещё не выбирался явно (новое поле `users.language_chosen boolean default false`, добавить в миграцию E1.1 или отдельной).
- Список языков с русскими названиями, одна кнопка на язык. Выбор — `POST /me/language`, затем обычный поток.
- Если язык один — экран пропускается, `language_chosen` не трогается.

Критерии: в браузере при одном языке экран не виден; при двух — виден один раз, после выбора не повторяется.

### E4.3 Смена языка из настроек

- На главной или в существующем экране настроек/профиля строка «Язык: Английский» с переходом на тот же `LanguagePick`.
- После смены: сброс кэшей клиента, перезагрузка главной, тем, кино, «Изучаю», статистики, счётчика.

Критерии: прогресс после переключения `en → fr → en` на месте в обоих языках.

### E4.4 Озвучка

Файлы: `packages/web/src/speak.ts`, `views/SpeakButton.tsx`.

- `speakWord(phrase, rate, voiceLang)`; `voiceLang` из конфигурации языка. Медленный режим `SLOW_SPEECH_RATE = 0.25` и обход `pause()/resume()` для Telegram на iPhone без изменений.
- Выбор голоса: первый доступный голос с нужным `lang`; если нет — системный по умолчанию без падения.

Критерии: на iPhone в Telegram французское слово читается французским голосом, медленный режим работает.

### E4.5 Карточки и режимы

- Все экраны, которые показывают английское слово (`Learn`, `Match`, `Recall`, `WordList`, `KnownMark`, словарь, статистика), читают `word`, не `en`.
- Подсказка рода на карточке, если `gender` есть: короткая пометка рядом с частью речи.
- Контрольная и экзамен: ввод сравнивается с `word`; правило одной опечатки сравнивает с другими `word` в пуле текущего языка. Артикль в вводе не требуется и не засчитывается как ошибка, если введено «le banque»/«la banque»: отрезать известные артикли языка перед сравнением.
- Пример к слову в фильме при `exampleTranslated` показывается как обычно; отдельной пометки на карточке не делать.

Критерии: тест API на обрезку артикля; браузерная проверка контрольной на французской теме с dev-пользователем, у которого вручную в базе выставлен `language='fr'` (после проверки вернуть `en`).

### E4.6 Скрытие недоступных входов

- На главной и в списках: словарь «Найти», «Добавь свой текст», кнопка заявки на фильм скрыты, если флаг возможности для текущего языка `false`.
- Бесплатный тариф на новом языке: 10 тем и 1 фильм; строка про текст в баннере не показывается, если `texts=false`.

Критерии: при `fr` главная без этих входов; при `en` всё как раньше.

### E4.7 Бот

Без изменений в тексте и кнопках. Проверить только, что `/start` и реферальные ссылки не зависят от языка.

## E5. Тесты, выпуск, включение французского

### E5.1 Тесты API
- Прогресс изолирован по языку.
- Контрольная/экзамен/опечатка — только пул текущего языка.
- Счётчик, бесплатные лимиты, «Изучаю», «Мои слова» — на язык.
- `POST /me/language` отклоняет код не из списка.
- Миграция на копии прод-базы без потерь (сравнить количество строк до и после по таблицам).

### E5.2 Релиз 2 с одним языком
- `pg_dump`, тесты, образ на копии базы, `docker compose up -d --build api`.
- Проверка: для пользователей ничего не изменилось.

### E5.3 Внутренняя проверка французского
- `data/fr` уже в образе, но `AVAILABLE_LANGUAGES=en`.
- Dev-пользователю вручную `language='fr'`. Пройти: главная, тема, Пары, Учить, Контрольная (на следующий день), фильм, озвучка в Telegram на iPhone, статистика, смена языка обратно.

### E5.4 Включение
- `AVAILABLE_LANGUAGES=en,fr`, перезапуск контейнера `api`.
- Откат: убрать `fr` из списка. Французский прогресс остаётся в базе.

## E6. После запуска (отдельные задачи, не входят в этот план)

- Разбор своего текста и «Найти» для нового языка: лемматизация и подсказки модели на целевом языке, затем `texts=true`, `dictionary=true`.
- Настоящие субтитры на целевом языке как отдельный источник пака (другой состав слов, другая карточка в каталоге).
- Уровни CEFR, пересчитанные под язык.
- Следующие языки: повтор E2–E3, строка в `AVAILABLE_LANGUAGES`.
